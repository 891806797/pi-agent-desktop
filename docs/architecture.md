# 模块职责与状态边界

本项目以 `prompt.md` 为功能范围：多人会话、多页面镜像、审批与提问、动态模型/思考/模式、输入队列、命令和文件引用。保留三包结构与现有页面样式。

## 后端

依赖方向：`routes → modules → core/env/common`。`core` 不依赖业务模块；`modules` 不依赖 Elysia 或路由。模块之间直接调用明确的能力，不增设单实现接口和转发层。

| 位置 | 职责 |
| --- | --- |
| `routes/index.ts` | 统一装配 API，最后处理前端静态资源与 SPA 回退；未知 API 保持 JSON 404。 |
| `routes/*` | 参数校验、身份接入、Cookie/HTTP/SSE 编解码、调用业务服务、返回响应；不扫描目录、不读写模型配置、不创建 SDK 会话。 |
| `modules/agent/agent.service.ts` | 经属主与工作区校验后，组织会话操作；生成消息与完整运行状态的同步快照。 |
| `modules/agent/session-registry.ts` | 活跃 SDK 实例、并发创建/恢复、用户运行时缓存、配额、回收与关闭清理。 |
| `modules/agent/session-recovery.ts`、`runtime-store.ts` | 记录运行、输入/附件、审批及工具检查点；对照 SDK 历史恢复未完成运行，未知副作用先暂停确认。 |
| `db`、`drizzle` | Drizzle 表结构、Bun SQLite 连接及官方迁移；编译版内嵌同一套迁移文件，不放业务执行逻辑。 |
| `modules/agent/model.service.ts` | 可用模型与用户 Provider 配置业务；原地刷新共享运行时，失败恢复旧配置。 |
| `modules/agent/event-translator.ts`、`history.ts` | 分别适配实时事件与历史内容，输出 common 契约；实时工具部分输出叠加进快照。 |
| `modules/agent/event-bus.ts` | 唯一事件定序、有限重放、订阅广播；断档或旧进程游标要求重新对账。 |
| `modules/agent/approval-manager.ts`、扩展适配 | 挂起、结算、取消、超时及清理；所有页面经总线接收同一审批状态。权限规则在工具执行边界生效。 |
| `modules/agent/queue-operations.ts` | 适配 SDK 缺少单条编辑的输入队列；串行应用侧修改、保留附件、识别 SDK 消费，失败保留尚未入队的输入。 |
| `modules/system` | 工作区注册、路径与物理边界校验、目录/文件列表、文件引用与静态资源。业务数据的内部持久化仍由数据所属模块组织。 |
| `modules/auth` | 用户记录、密码校验、JWT 签发与验证。Cookie 解析及写入位于 routes 的 HTTP 接入层。 |
| `core`、`env.ts` | 错误码、异常/响应格式、校验入口、框架错误边界、环境配置。 |

连续的业务流程在服务内保持完整；审批、队列和事件各自拥有独立生命周期，因此单独组织。文件划分以职责和维护边界为准，不为单个辅助函数建立模块。

## 状态的唯一归属

- pi SDK 拥有消息上下文、实际模型/思考档位和执行/输入队列；Web 不另建一套执行状态机。
- Registry 拥有实例的创建与关闭；总线状态仅投影 SDK 事件及挂起审批，不能作为新的执行控制源。
- Translator 为每个活跃会话分配 Web 消息 UUID，SSE 与快照共用同一身份表，避免同毫秒消息冲突；进程重启时通过完整快照重建身份。
- 审批管理器独占当前进程的 pending Promise；创建和结算先持久化，再广播和恢复 SDK。重启重建 Promise 与剩余计时，不重新创建审批身份；定时结算写盘失败保留卡片并重试，不能先授权。
- 队列正常时以 SDK 为准。仅当 SDK 拒绝恢复时保留未插入输入及附件，广播明确错误并支持重试/清空；含队列或恢复副本的会话不被空闲回收。
- 快照同步读取完整 messages、在途消息、工具部分结果、审批、队列、模式与 seq；页面先应用快照，再接收该 seq 之后的增量。

## 前端与 common

- `SessionConnection` 管理 attach/resume/重新对账和连接代次；旧连接回调不能修改新会话。
- URL 是当前项目与会话坐标的唯一来源；项目列表请求只更新列表。切换时关闭旧 SSE、清空消息/审批/队列，再原子应用新快照；旧列表请求、旧快照和旧页面操作回调失效。切页不停止服务端会话。
- SSE 客户端只负责协议、游标、心跳与重连通知；store 负责渲染状态。恢复都回到同一快照入口。
- 消息与审批组件直接消费 common.ChatMessage/AssistantBlock/PendingRequest；不再保留 gzh/Claude 的第二套消息类型、XML 元数据解释、工具别名和人设/子代理/回滚占位。用户原文和工具结果不会因看起来像旧框架标签而被删除。
- 助手正文使用 Markdown；工具正文按原文保留换行和缩进，JSON 对象仅格式化。长输出折叠预览，展开后可滚动查看完整尾部；参数和 SDK details/diff 按需披露。输出长度限制有明确提示，未完成工具不残留运行状态。用户图片在实时与历史保留，附件 MIME 沿用实际图片格式。
- `/new`、`/compact` 的定义在 common 中共享，空白页也可补全；其他候选来自 SDK 的真实资源。补全选择只插入草稿，参数由用户继续填写。`/new` 只切换新草稿坐标，旧后台运行继续；`/compact` 调用 SDK 压缩。
- 桌面保持可调侧栏；窄屏复用同一导航内容，通过 Base UI 对话框访问。切换会话关闭弹层，跨桌面断点释放焦点与遮罩。思考和工具折叠为原生按钮，支持键盘与 aria-expanded。
- 顶栏统计沿用 pi TUI footer 口径：SDK getSessionStats() 累计全部持久化条目的 input/output（input 不含单独计算的缓存读写）；缓存命中率是最后一条助手消息的 cacheRead/(input+cacheRead+cacheWrite)，不做累计平均。上下文直接使用 SDK getContextUsage()，压缩后未知值保留 null。会话快照和 session_metrics SSE 共用此投影，消息落盘后的微任务合并广播，避免少计最后一条或每个 delta 扫描历史；切页清空旧统计。
- 首条发送创建成功即保存坐标；模式初始化失败后可在同一会话重试。SDK 接受消息后才清除对应草稿，异步失败、切页或等待中的编辑不会丢稿。
- 模型与思考强度的修改复用会话变更事务，避免认证等待导致乱序；关闭也等待最后配置写入。已发出的模型请求保持原配置，下一次 SDK 请求读取新模型和有效思考档位；运行模式在后续工具执行边界读取，审批等待后还会重新检查计划模式限制。
- 运行中回车默认 `followUp`，当前任务结束后继续；空闲直接发送。队列每项的“立即发送”可选择 `steer`（不停止当前请求，在 SDK 边界优先切入）或停止后发送。停止后发送等待 SDK 接受及初始用户消息事件，再恢复其他两轨及附件；同文条目也不误删。队列版本阻止过期操作，请求标识防止重复发送，失败保留未接受输入。
- 权限审批与 AskUserQuestion 的五分钟截止时间由服务端创建并随快照重放，切页不重计。权限到期按当时运行模式处理：safe 拒绝，其他模式允许；计划模式仍在执行边界阻止写入。提问到期逐题以“请自主决策”形成系统默认工具结果。用户提交、超时、中断、关闭共用一次性结算，所有页面移除同一卡片。
- 压缩实时事件与历史快照使用同源身份显示摘要和 token，重放不重复；取消或失败不展示成功。模型错误属于原助手消息，重试耗尽不重复追加；中止、失败后的工具不保留运行状态。收到会话关闭事件后停止 SSE 恢复，不自动重开已关闭会话。
- `common/messages.ts` 定义渲染数据和共享枚举，`common/sse-events.ts` 定义事件协议，`common/dto` 定义请求 Zod 单源与响应类型。共享纯能力也应归入 common；文件系统、SDK 实例、业务服务及用户凭据不进入 common。
- 目录操作使用 `node:path`，Web 消息 UUID 使用 `crypto.randomUUID()`，会话 UUID 沿用 pi SDK，JWT 使用 `jose`，密码哈希使用 Bun.password；不自行实现相关算法。

## 明确的 SDK 边界

pi 没有公开的原子单条队列编辑接口。Web 重灌队列时会保留两轨输入与附件，并处理 SDK 同时消费导致的部分成功；以 `/` 开头、可能再次展开的原始内容拒绝重排并保留原队列，避免重复解释命令。此限制以可见错误反馈，不能静默丢输入。

磁盘扩展在加载前禁用；Web Provider 配置不允许执行认证命令或读取服务器环境变量。TUI 的自定义终端组件不直接迁入浏览器，Web 使用声明式提问和审批。当前 UIContext 只完整桥接 select/confirm/input，并非完整扩展 UI 宿主；notify、status、文本 widget 和 editor 等也尚未接入，不能混同为终端专属能力。完整对照及未覆盖项见 `docs/pi-tui-web-coverage.md`。

SDK 不持久化压缩后的 token 估算；重启后保留摘要与压缩前 token，缺失估算不显示。

单实例重启由 `DATA_DIR/runtime.sqlite`（Drizzle ORM、SQLite WAL + FULL）与 SDK JSONL 协作恢复。JSONL 拥有上下文和已完成结果；SQLite 保存正在运行的检查点、队列及图片、审批原始载荷和绝对截止时间、工具开始/完成记录。启动扫描与页面 resume 复用同一注册表锁，校验用户和工作区；用户中止或关闭会清除可恢复运行，正常进程退出只暂停并保留检查点。

旧连接和 Promise 不复活：未完成模型轮次以 SDK 公开入口重新发起；工具通过 SDK `runToolCall` 执行，复用参数规范化、校验和权限钩子。已落 JSONL 或已持久化完成结果的工具不再执行；length/error/aborted 响应里的未执行工具只补失败结果。已开始但结果未知的工具先形成中断结果并显示恢复确认，用户检查后才继续，不能自动重跑。无法保证文件/外部命令与本地记录跨系统恰好一次，因此这一窗口明确暂停。

权限和提问沿用 requestId、createdAt、expiresAt，停机时间计入原五分钟。恢复时已过期的权限按当前模式默认结算，Ask 每题回复“请自主决策”。同文队列以稳定身份保留附件，恢复首条用户消息后才灌入其余队列，避免 SDK 按文本消费时误删下一条。损坏检查点拒绝自动执行，保留原数据供检查。

## 前端运行时验收

自动测试覆盖项目/会话快速切换、旧回调隔离、模型与思考修改顺序、配置与关闭竞争、审批并发结算与五分钟假时钟、队列并发派发及附件恢复、错误与压缩实际组件渲染。HTTP 测试使用本地模拟 Provider 驱动真实 SDK，并以三个 SSE 连接验证共同事件序列。

`packages/frontend/test/browser_acceptance.py` 使用已安装的 Python Playwright 和编译版进行真实无头 Chromium 验收：登录、三个标签页、后台审批后返回重放、强制重启恢复权限及提问的原卡片与截止时间、一页结算全页清卡、思考中切页及队列菜单；另验收原生命令、工具换行和完整尾部、键盘、窄屏导航、顶部 TUI 统计及压缩/刷新。数据与工作区均为临时目录，Provider 只监听本机；子服务首次使用系统分配端口，重启复用已确认的子进程端口，必须读到成功绑定日志后才测试。

Windows 示例（先构建前端与编译版）：`python packages/frontend/test/browser_acceptance.py <exe绝对路径> <bun.exe绝对路径> [chromium绝对路径]`。五分钟规则用可控假时钟验证，浏览器验收不实际等待五分钟；未验证真实外部 Provider 成功响应及 Linux/macOS 运行。
