# 单实例重启恢复实施计划

> 使用 superpowers:executing-plans 按任务内联执行，最终独立复审。以当前会话用户要求与下述边界为验收依据。

**目标：** 服务重启后自动恢复未完成的模型轮次和待审批/提问；保留原 requestId、载荷和绝对截止时间。用户已明确：已开始执行但结果未知的工具必须暂停，用户检查确认后才继续，不自动重跑。

**架构：** pi JSONL 继续拥有聊天上下文和已完成工具结果；agent 模块使用 Drizzle ORM + Bun 内置 SQLite 的原子事务保存可恢复的运行检查点。数据库位于 DATA_DIR，记录属主、会话、工作区、运行状态、输入队列/附件、审批及结算、工具执行记录。表结构使用 Drizzle Kit 生成迁移，Bun 安装最新依赖。只使用 SDK 公开 API，不调用私有 _startRun 或替换 streamFn 伪造模型响应。

**恢复语义：** 旧网络连接不能复活；未完成的模型请求从持久化上下文重新发起。已落盘/已持久化完成结果的工具绝不重跑；等待权限和提问的调用重建同一审批及剩余期限。停机时间计入五分钟，已到期项立即按原规则结算。结果未知的工具形成中断结果并暂停在显式恢复确认处；确认后继续模型流程，先核对实际状态。

## 模块与边界

- `modules/agent/runtime-store.ts`：SQLite 检查点读写、版本/形状校验、删除与资源关闭；不加载 SDK、不操作 HTTP。
- `modules/agent/session-recovery.ts`：会话检查点、SDK 事件与审批持久化、恢复输入/工具和模型运行。恢复调用使用 SDK 公开 `runToolCall`，沿用参数准备、校验与 beforeToolCall/afterToolCall；不另造 AgentLoop。
- `approval-manager.ts`：接入可选持久化回调，创建和结算先落盘；恢复已有请求时沿用原时间和一次性结算。
- `session-registry.ts`、入口：启动扫描可恢复会话并校验用户/工作区，复用现有并发恢复锁与配额；区分用户关闭和进程暂停。关闭/中止不被重启误恢复。
- `queue-operations.ts`：导出已有队列元数据并在恢复时保留轨道、次序和附件，不重复展开已准备的命令文本。
- 前端复用现有审批 dock 呈现恢复确认与中断原因，多页面仍从快照与 SSE 获得同一状态。

## 验证结果

- 后端 116 项 / 478 个断言，前端 38 项 / 135 个断言全部通过；三包类型检查、Biome、Drizzle Kit check、Vite 构建与 Windows 单文件编译通过。
- 编译版 Chromium 三页面验收通过：权限和提问分别强制重启，原卡片身份/截止时间不变，一页处理后其他页自动清卡；已有切页、队列、工具换行、统计和压缩刷新流程无页面错误。
- 独立复审的恢复专项 29 项 / 223 个断言通过，未发现剩余 P1/P2。额外补齐截断/取消响应不执行工具、legacy edit 参数规范化、同文异图队列首条消费时序、写盘失败内存回滚和异步异常处理。
- `bun update --latest --recursive` 更新工作区依赖，新增依赖经 `bun add ...@latest` 解析；`bun outdated --recursive` 无过期项。版本与锁文件由 Bun 写入，迁移由 Drizzle Kit 生成。
- 测试临时目录使用 D 盘，避开 C 盘空间不足；未使用开发服务数据。到期恢复测试使用已到期的持久化绝对时间模拟停机超过五分钟，没有实际等待五分钟；未验证外部 Provider 成功响应或非 Windows 可执行文件。

## 必查异常

检查点不能让已删除用户或越界工作区执行；恢复记录损坏时不猜测执行。SDK 原始历史优先于旧检查点，避免在写入结果后、清理检查点前崩溃造成重复执行。恢复创建与浏览器 resume 合并，关闭及再次重启必须清理计时器与连接。任意外部命令在执行成功与结果落盘之间的窗口只能标记未知，不能声称可保证外部副作用恰好一次。
