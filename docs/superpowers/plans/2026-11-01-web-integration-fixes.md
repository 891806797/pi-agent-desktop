# Web 对接缺陷修复计划

**目标：** 以根目录 prompt.md 和实施计划.md 为验收依据，保持当前页面样式与三包架构，修复已对接功能的架构、状态和接口缺陷。

**范围：** 多用户会话隔离、会话创建/恢复/回收、流式快照与增量事件、审批、队列、模型/思考/模式切换、命令与文件引用，以及现有单文件构建的启动闭环。不新增会话树、分支、分享、导入导出，不引入依赖，不提交推送。

**实现约定：** SDK 操作的成功以实际执行结果为准；初始快照包含 messages、seq 和 SessionInfoResponse 的状态，读取过程同步完成；前端先应用完整快照再从 seq 订阅，重连走同一恢复入口。只允许指定的内联扩展，必须在加载前阻止磁盘扩展执行。队列换轨由后端一次完成，保留另一类队列。

## 边界验证重点

1. 其他用户/其他 workspace 的 sessionId 不可操作，路径同名前缀与符号链接不可越界。
2. 生成中或等待审批时刷新、新开页面、断线、服务重启，快照和增量保持一致。
3. 并发恢复、重复审批、重复队列操作、切换页面后的异步结果不能破坏当前会话。
4. 无认证、SDK 拒绝/降档、压缩或重试中提交/中断，有明确反馈并可恢复。
5. 保留用户文件与现有页面样式；缺少真实 Provider 联调证据必须如实注明。
